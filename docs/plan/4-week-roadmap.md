# W0 + 4주 로드맵 — 디자인 파운데이션 + 1차 MVP 완성

> **원칙: 디자인 토대 → 보이는 것 채우기 → 실 API 정착 → 품질/배포**

## 라우트 맵 (전체)

### 공개 (비로그인 접근 가능)

| 라우트                            | 설명                                                            |
| --------------------------------- | --------------------------------------------------------------- |
| `/`                               | 홈 — `?tab=explore` 탐색(검색/지도/랭킹), `?tab=my` 비로그인 CTA |
| `/restaurant/[id]`                | 맛집 상세 — 비로그인은 미리보기(리뷰 2~3개 + 로그인 CTA)        |
| `/user/[id]`                      | 타 유저 프로필 — 잠금 화면                                      |

### 인증

| 라우트                            | 설명                                                            |
| --------------------------------- | --------------------------------------------------------------- |
| `/login?next=<원래 경로>`         | 로그인 진입점 (구글 OAuth)                                      |
| `/signin`                         | NextAuth 콜백/대체 로그인                                       |
| `/onboarding`                     | 닉네임/지역 입력 (최초 로그인 후)                               |

### 보호 (로그인 필요 — middleware 가드)

| 라우트                            | 설명                                                            |
| --------------------------------- | --------------------------------------------------------------- |
| `/profile`                             | 내 프로필 (뱃지/레이더/TOP3)                                    |
| `/profile/grade`                  | 등급 안내 (현재 등급 + 체크리스트 + 타임라인)                   |
| `/my-places?tab=ranking\|wishlist`| 내 맛집 지도 (랭킹 / 가고 싶은)                                 |
| `/review/new?restaurantId=...`    | 리뷰 작성 폼 (전역 진입점)                                      |
| `/restaurant/[id]/review/new`     | 맛집 상세에서 진입한 리뷰 작성 — `/review/new`와 통일 검토 (W3) |
| `/review/new/result?reviewId=...` | 리뷰 제출 결과 (게이지/체크리스트/등급 진행바)                  |

### 에러

| 라우트                            | 설명                                                            |
| --------------------------------- | --------------------------------------------------------------- |
| `not-found.tsx` (전역)            | 404                                                             |
| `error.tsx` (전역)                | 런타임 에러 + 다시 시도                                         |
| `/restaurant/[id]/error.tsx`      | 맛집 상세 전용 에러 (잘못된 ID 등)                              |

### 미들웨어 가드 (W2 Day 5)

`src/proxy.ts`에서 보호 경로 진입 시 비로그인 → `/login?next=<원래 경로>` 리다이렉트:

```
/profile, /profile/*, /my-places, /review/*
```

## 프로토타입 → 내 코드 표준 절차 (W2부터 적용)

화면 단위로 7단계 반복. **W2 Day 2의 `/profile`가 첫 레퍼런스**.

1. **백엔드 endpoint 확인** — 스펙/응답 스키마/에러 코드
2. **타입 분할** — `src/lib/types/<feature>/{type,response,request}.ts`로 분할
3. **API 함수 생성** — `src/api/<feature>/<feature>.ts`에 `getX()` (axios 호출)
4. **React Query 훅** — `src/hooks/<feature>/use-<x>.ts`
5. **페이지 전환** — `'use client'` + 훅 사용, Skeleton / Empty / Error 상태
6. **`common/` 의존성 정리** — `core/<kebab>/index.tsx`로 이동
7. **체크** — `pnpm lint`, `npx tsc --noEmit`, 브라우저에서 실 데이터 동작 확인
