# 인증 기획서

> API 계약은 [`backend-spec.md`](./backend-spec.md) 참조.

---

## 1. 화면 구성

인증과 관련된 화면은 로그인(`/signin`)과 온보딩(`/onboarding`) 두 가지다.

---

## 2. 로그인 화면 (`/signin`)

### 진입 경로

비로그인 상태에서 인증이 필요한 행동을 하면 로그인 안내 팝업이 뜬다. 팝업의 "로그인하기" 버튼을 누르거나, 헤더의 로그인 버튼을 직접 누르면 로그인 화면으로 이동한다.

### 화면 구성

- **TrustBite 브랜드 타이틀**과 서비스 소개 문구
- **"Google로 시작하기" 버튼** — 현재 Google OAuth만 지원
- 서비스 약관·개인정보처리방침 동의 안내 문구

### 로그인 후 이동

로그인이 완료되면 사용자가 로그인 전에 보고 있던 페이지로 돌아간다. 이전 페이지가 없으면 홈(`/`)으로 이동한다.

---

## 3. 온보딩 화면 (`/onboarding`)

최초 로그인 직후에만 진입한다. 서비스에서 나를 표현하는 기본 정보를 설정한다.

### 입력 항목

- **프로필 사진** — 선택 사항. Google 계정 사진이 기본으로 표시되며, 사용자가 직접 교체할 수 있다. 사진을 교체하지 않으면 Google 사진이 그대로 사용된다.
- **닉네임** — 필수. 2~12자. 서비스 내 표시 이름으로 쓰인다.

### 동작

닉네임을 입력하고 "시작하기"를 누르면 홈으로 이동한다. 프로필 사진은 변경하지 않아도 진행할 수 있다.

---

## 4. 로그아웃

내 프로필 화면에서 로그아웃할 수 있다. 로그아웃하면 로그인 화면으로 이동한다.

---

## 5. 로그인 여부에 따른 화면 분기

TrustBite는 비로그인 상태에서도 탐색·상세 조회가 가능하다. 단, 일부 행동은 로그인이 필요하다.

| 화면·요소 | 로그인 상태 | 비로그인 상태 |
|---|---|---|
| 헤더 우측 | 아바타 + 닉네임 | 로그인 버튼 |
| 헤더의 인증 필요 탭 | 탭으로 이동 | 로그인 안내 팝업 |
| 가게 카드의 북마크 버튼 | 즉시 저장·취소 | 로그인 안내 팝업 |
| 맛집 상세 북마크 버튼 | 즉시 저장·취소 | 로그인 안내 팝업 |
| 맛집 상세 리뷰 목록 | 전체 리뷰 표시 + "더보기" | 리뷰 2개만 표시, 더보기 시 로그인 안내 팝업 |
| 맛집 상세 "리뷰 쓰기" 버튼 | 리뷰 작성으로 이동 | 로그인 안내 팝업 |
| 내가 쓴 리뷰 영역 | 표시 | 숨김 |
| 내 프로필 (`/profile`) | 접근 가능 | 로그인 화면으로 리다이렉트 |

### 로그인 안내 팝업

비로그인 상태에서 인증이 필요한 행동을 하면 팝업이 뜬다. "로그인하기"를 누르면 로그인 화면으로 이동하되, 완료 후 원래 보던 페이지로 복귀한다. "나중에"를 누르면 팝업이 닫힌다.

---

## 6. 세션 유지 정책

- **NextAuth 세션**: 7일 (rolling). 이게 "로그인 유지"의 실체.
- **백엔드 accessToken**: 30분. 만료(401) 시 refreshToken으로 자동 갱신.
- **백엔드 refreshToken**: HttpOnly 쿠키. 7일 (NextAuth 세션 만료와 맞춤).
- refreshToken까지 만료되면 재로그인이 필요하다.

---

## 7. 미정 항목

- **프로필 사진 용량·형식 제한**: 최대 파일 크기, 허용 형식(JPEG/PNG/WEBP 등) 확정 필요.
- **서버측 라우트 보호**: onboarding gate는 미들웨어(`src/proxy.ts`)로 처리 확정. 그 외 인증 필요 라우트(`/profile`, `/my-places`, `/review/*`) 목록은 확정 필요.
- **로그아웃 엔드포인트**: `POST /api/auth/logout` 명세 미확정 (refreshToken 쿠키 무효화 여부 포함).
