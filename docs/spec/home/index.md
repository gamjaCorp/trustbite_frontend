# 홈 화면 기획서

> 검색창 인터랙션은 [`search.md`](./search.md), API 계약은 [`backend-spec.md`](./backend-spec.md) 참조.

---

## 1. 화면 한눈에 보기

화면은 크게 세 영역으로 나뉜다. 상단에 검색창·필터·지도가 고정되고(sticky), 그 아래 검색 결과 리스트가 스크롤된다. 지도와 리스트는 항상 같은 데이터를 가리킨다.

- **지도 (상단 고정)** — 검색된 맛집 위치에 핀이 표시된다.
- **검색·필터 영역** — 검색 입력창 + 카테고리 필터 칩. 검색 동작은 `search.md` 참조.
- **결과 리스트 (하단 스크롤)** — 랭킹 순서대로 가게 카드가 나열된다.
- **인트로 카드** — 서비스 첫 방문 시 리스트 맨 위에 표시되는 신뢰도 소개 카드. 2장 참조.
- **"리뷰 쓰기" 버튼 (우하단 고정)** — 화면 오른쪽 아래에 항상 떠 있는 플로팅 버튼. 누르면 리뷰 작성 페이지로 이동한다.

> PRD §7.2의 "리스트 우선 70-80% + 시트 인터랙션" 모델은 1차 MVP에서 채택하지 않는다 (7장 참조).

---

## 2. 인트로 카드

서비스를 처음 방문한 사용자에게 신뢰도 기반 맛집 추천 개념을 소개하는 카드다. 카드에는 신뢰도 비교 예시("신뢰도 88%" 등)와 "둘러볼래요" CTA, 닫기(X) 버튼이 있다.

**닫는 방법은 두 가지다.**

- "둘러볼래요" 버튼을 누른다.
- 우측 상단 X 버튼을 누른다.

어느 쪽으로 닫아도 브라우저에 기억되어, 이후 방문 시 다시 표시되지 않는다. 로그인 여부와 무관하게 동작한다.

## 3. 지도

### 화면 진입 시

사용자의 현재 위치(또는 기본 위치)를 중심으로 지도와 결과 리스트가 함께 로드된다.

### 지도를 이동하면 — "이 지역에서 검색"

지도를 드래그하거나 줌을 바꾸면 화면이 보여주는 영역과 실제 검색 결과가 어긋나게 된다. 이때:

1. 리스트 상단(또는 지도 위)에 **"이 지역에서 검색"** 버튼이 나타난다.
2. 버튼을 누르면 현재 지도에 보이는 영역(중심 좌표 + 반경)으로 다시 검색한다.
3. 리스트와 핀이 새 영역 결과로 갱신되고 버튼은 사라진다.

버튼을 누르지 않는 동안에는 리스트 내용이 바뀌지 않는다.

**"이 지역에서 검색"과 "더 불러오기"는 동시에 나타나지 않는다.**

- 지도가 검색 영역과 일치할 때 → "더 불러오기"만 표시 (결과가 더 있을 경우)
- 지도가 검색 영역과 어긋날 때 → "이 지역에서 검색"만 표시, "더 불러오기"는 숨김

### 핀 종류

TrustBite 리뷰 데이터가 쌓인 가게와 그렇지 않은 가게를 핀 모양으로 구분한다.

- **순위 번호 핀** — TrustBite에 실제 리뷰·평점 데이터가 있는 가게. 1위는 금색, 2위는 은색, 3위는 동색, 그 외는 회색 배경에 순위 번호가 표시된다.
- **카테고리 아이콘 핀** — 아직 리뷰 데이터가 부족한 가게. 브랜드 컬러 배경에 음식 카테고리 아이콘이 표시된다.
- **방문 체크 핀** — 기본 핀 위에 체크 마크를 겹쳐 표시. 내가 리뷰를 남긴 가게에 사용된다. *(미구현 — 7장 참조)*

2차 MVP에서 trustScore 기반 색상 차등(골드: 80%+, 그린: 50~80%, 그레이: 50% 미만) 추가 예정(PRD §5.2).

### 핀 이름 라벨

핀 아래에 가게 이름이 담긴 말풍선 형태의 라벨이 표시된다.

- **선택된 핀** — 항상 라벨이 표시된다. 테두리가 브랜드 컬러로 강조된다.
- **충분히 확대된 상태** — 지도를 가까이 확대하면(거리 수백 미터 이내 수준) 검색 결과 내 모든 핀에 라벨이 함께 표시된다. 이때도 선택된 핀 라벨만 브랜드 컬러 테두리로 강조된다.

지도를 다시 축소하면 선택된 핀 라벨만 남고 나머지는 사라진다.

## 4. 결과 리스트

### 리스트 상단 타이틀

리스트 맨 위에 **"{지역명} 일대 맛집"** 형태의 타이틀과 **"이 영역에 N곳"** 개수가 표시된다.

- 지역명은 현재 지도 중심을 역지오코딩한 법정동/행정동 이름이다.
- Focus 모드(6장)에서는 확정한 가게의 주소 기반 지역명으로 교체된다.
- N은 현재 화면에 불러온 가게 수 기준이다. "더 불러오기" 전에는 최대 30이다. *(전체 결과 수 표시 여부는 7장 참조)*

### 로딩·빈 상태

**불러오는 중**: 리스트 자리에 가로 막대 형태의 스켈레톤이 표시된다.

**결과 없음**: "이 지역엔 맛집이 없어요" 메시지와 "새 맛집 추가하기" 버튼이 표시된다. *(가게 추가 흐름은 7장 참조)*

### 가게 카드 항목

모든 카드에 공통으로 표시되는 항목:

- **순위 메달** — TrustBite 랭킹 순서. 리뷰 데이터가 없는 신규 가게에는 표시하지 않는다.
- **가게 이름** — 오른쪽에 `↗` 아이콘이 붙어, 클릭 시 상세 페이지로 이동함을 나타낸다.
- **카테고리** — 한식, 일식, 중식 등 음식 종류.
- **TrustScore** — 0~100 범위의 신뢰도 점수.
- **커뮤니티 평균 별점** — 0~5 범위. 리뷰 데이터가 없는 가게에는 별점 대신 "리뷰 부족" 안내가 표시된다.
- **대표 이미지** — *(이미지 소스 정책은 7장 참조)*
- **북마크 버튼** — 항상 표시. 로그인 상태에서 누르면 위시리스트에 저장·취소를 토글한다. 비로그인 시 누르면 로그인 안내가 표시된다.
- **"신규" 배지** — 리뷰 데이터가 부족한 가게에만 표시된다.

로그인 상태에서 본인이 기록한 가게에 한해 추가로 표시되는 항목:

- **본인 코멘트** — 내가 남긴 리뷰의 한 줄 메모. 리뷰를 쓴 가게에만 표시된다.
- **액션 버튼** — 카드 우측에 표시. 리뷰를 아직 쓰지 않은 가게에는 "리뷰 쓰기", 이미 쓴 가게에는 "수정"이 표시된다.

### 카드 클릭 영역

카드 내 어떤 영역을 클릭하느냐에 따라 동작이 달라진다.

| 클릭 영역 | 동작 |
|---|---|
| 카드 본체 (가게 이름·코멘트·액션 버튼 제외, 썸네일 포함) | 지도가 해당 가게로 클로즈업. 리스트와 검색 결과는 그대로 유지 |
| 가게 이름 | 가게 상세 페이지로 이동 |
| 본인 코멘트 줄 | 가게 상세 페이지로 이동 |
| 댓글 아이콘 + 리뷰 개수 | 가게 상세 페이지로 이동 |
| "리뷰 쓰기" / "수정" 버튼 | 리뷰 작성 페이지로 이동 |

### 카테고리 필터

리스트 상단 칩(한식 / 일식 / 중식 / 양식 / 분식 / 치킨 / 패스트푸드 / 카페 / 술집 / 전체)을 누르면 해당 카테고리만 표시된다. 필터를 바꾸면 처음부터 다시 검색한다.

### 정렬

리스트 헤더 우측 드롭다운에서 선택한다. 정렬을 바꾸면 처음부터 다시 검색한다. 1차 MVP에서는 UI는 보이되 비활성화 상태로 표시한다. 백엔드 정렬 파라미터 API 완료 시 활성화 예정.

- **랭킹순** (기본) — 내부 랭킹 기준 오름차순. 랭킹 계산식은 커뮤니티 평균 별점 내림차순, 동점 시 TrustScore 내림차순이 권장안이다. *(확정 필요 — 7장 참조)*
- **신뢰도순** — 가게 TrustScore 내림차순. 신뢰할 수 있는 리뷰가 많이 쌓인 가게를 우선 표시한다.
- **최신순** — 가장 최근 리뷰 작성 시각 기준 내림차순. 트렌드성 가게를 발견하는 데 적합하다.

### 상황 필터 (2차 MVP)

"혼밥 / 데이트 / 회식 / 다이어트" 같은 상황 태그로 검색 결과를 좁히는 필터다. 1차 MVP에서는 노출하지 않는다. 백엔드의 sceneTag 집계 API가 준비되면 활성화한다.

### "더 불러오기"

리스트는 자동으로 계속 불러오지 않는다. 직접 버튼을 눌러야 한다.

- 처음에는 30개를 표시한다.
- 결과가 더 있으면 리스트 맨 아래에 **"N개 더 불러오기"** 버튼이 표시된다.
- 버튼을 누르면 다음 30개가 리스트 아래에 이어 붙는다 (기존 결과를 덮어쓰지 않는다).
- 지도 핀도 새로 불러온 가게까지 포함해 함께 갱신된다.

## 5. 핀 ↔ 리스트 동기화

지도 핀과 리스트 카드는 서로 연결되어 있다.

- **핀을 클릭하면** → 해당 가게의 리스트 카드 위치로 자동 스크롤하고 카드를 강조 표시한다.
- **카드를 클릭하면** → 지도에서 해당 핀을 강조하고 그 가게로 클로즈업한다. 선택된 핀에는 이름 라벨(브랜드 컬러 테두리)이 표시된다.

이때 리스트 내용과 검색 영역은 그대로 유지된다. 아래 6장의 Focus 모드(리스트와 검색까지 전부 좁히는 상태)와 다른 점이다.

---

## 6. Focus 모드

**검색창에서 특정 가게를 선택·확정**하면 그 가게 하나에만 집중하는 상태가 된다. 검색 입력창 동작은 `search.md` 참조.

Focus 모드가 켜지면:

- **지도** — 핀이 1개만 표시되고 해당 가게로 클로즈업된다.
- **리스트** — 가게 카드 1개만 표시된다.
- **"이 지역에서 검색" / "더 불러오기" 버튼** — 숨겨진다.
- **리스트 타이틀 지역명** — 확정한 가게의 주소 기반 지역명으로 교체된다.

지도를 드래그하거나 줌을 바꿔도 Focus 모드는 유지되고 결과가 바뀌지 않는다.

**Focus 모드가 해제되는 조건**은 다음 중 하나다.

- 검색창 입력을 지운다 (Clear/X 버튼 또는 직접 지우기)
- ESC 키를 누른다
- 검색어를 수정한다 (타이핑)
- 다른 가게 항목을 확정한다
- 지역 이동을 확정한다
- 헤더 로고를 클릭한다 (페이지 초기화)

## 7. 미정 · 논의 필요

- **랭킹 정렬 기준** — 커뮤니티 평균 별점 내림차순, 동점 시 TrustScore 내림차순이 권장안. 확정 필요.
- **지도 핀 표현 방식** — 현재 구현은 "실 데이터 유무"로 순위 번호 핀 vs 카테고리 아이콘 핀을 구분한다. 초기 기획의 "브랜드 컬러 단일 핀 / 잠정 가게 회색 핀" 방향과 다름. 어떤 방향이 맞는지 확정 필요.
- **대표 이미지 소스** — 현재 플레이스홀더(카테고리 아이콘) 사용 중. 백엔드 이미지 정책 미정.
- **결과 개수 표시 기준** — 현재 "이 영역에 N곳"은 불러온(보이는) 개수 기준. 전체 결과 수를 별도로 보여줄지 논의 필요.
- **거리 표시** — 백엔드는 검색 중심 기준 직선 거리를 반환하나, 현재 카드에는 거리가 표시되지 않음. 표시 여부·기준점(검색 중심 vs 사용자 현재 위치) 논의 필요.
- **지역 필터 UI** — 시/도 → 시/군/구 두 단계 드롭다운. 검색바·"이 지역에서 검색"이 우선 커버 중이므로 백엔드 지역 API 준비 후 논의.
- **방문 체크 핀** — 백엔드 myStatus API 연동 후 구현 예정.
- **"새 맛집 추가하기" 흐름** — 빈 결과 상태의 CTA. 가게 추가 방식·백엔드 흐름 미정.
- **시트(bottom sheet) 레이아웃** — PRD §7.2의 리스트 70-80% 우선 모델. 1차 MVP 이후 UX 검토 후 결정.
