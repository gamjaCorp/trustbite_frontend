# 홈 화면 기획서

> 검색창 인터랙션은 [`search.md`](./search.md), API 계약은 [`backend-spec.md`](./backend-spec.md) 참조.

---

## 1. 화면 구조

상단에 검색창·필터·지도(고정 높이)가 sticky로 붙고, 그 아래 결과 리스트가 스크롤된다. 지도와 리스트는 항상 같은 데이터를 가리킨다. PRD §7.2의 "리스트 우선 70-80% + 시트 인터랙션" 모델은 1차 MVP에서 채택하지 않는다(향후 논의).

- **지도 (상단 고정)** — 검색된 맛집 위치에 핀이 꽂힌다.
- **리스트 (하단 스크롤)** — 랭킹 순서대로 가게 카드가 나열된다.
- **검색·필터 영역** — 검색 입력창 + 카테고리 필터 칩. 검색 동작은 `search.md` 참조.

## 2. 지도 인터랙션

### 기본 상태

화면 진입 시 사용자의 현재 위치(또는 기본 위치)를 중심으로 지도와 결과 리스트가 함께 로드된다.

### 지도 이동 시 — "이 지역에서 검색" 버튼

지도를 드래그하거나 줌을 바꾸면 화면과 검색 결과가 어긋난다. 이때:

1. 리스트 상단(또는 지도 위)에 **"이 지역에서 검색"** 버튼이 나타난다.
2. 버튼을 누르면 현재 보이는 지도 영역(중심 좌표 + 반경)으로 재검색한다.
3. 리스트와 핀이 새 영역으로 갱신되고 버튼은 사라진다.

버튼을 누르지 않는 동안에는 결과가 바뀌지 않는다.

### "이 지역에서 검색"과 "더 불러오기"는 동시에 표시되지 않는다

- 지도가 검색 영역과 **일치** → "더 불러오기"만 표시 (결과가 더 있으면)
- 지도가 검색 영역과 **어긋남** → "이 지역에서 검색"만 표시, "더 불러오기"는 숨김

### 지도 핀 종류

1차 MVP에서는 단일 색상 핀(브랜드 컬러)을 기본으로 사용한다.

- **일반 핀** — 브랜드 컬러. 검색 영역 내 맛집 전체.
- **잠정 핀** — 회색. TrustBite 리뷰 데이터가 부족해 순위가 잠정값인 가게.
- **방문 체크 핀** — 기본 핀 위에 체크 마크를 겹쳐 표시. 내가 리뷰를 쓴 가게(`myStatus === 'reviewed'`). *(현재 미구현 — §6 참조)*

2차 MVP에서 trustScore 기반 색상 차등(골드: 80%+, 그린: 50~80%, 그레이: 50% 미만) 추가 예정(PRD §5.2).

### 핀 이름 라벨

핀 아래에 가게 이름이 담긴 말풍선 형태의 라벨이 표시된다. 표시 조건은 두 가지다.

- **선택된 핀** — 항상 표시. 테두리가 브랜드 컬러로 강조되어 다른 라벨과 구분된다.
- **충분히 확대된 상태** — 지도를 가까이 확대하면(거리 수백 미터 이내 수준) 검색 결과 내 모든 핀에 라벨이 함께 표시된다. 이때도 선택된 핀 라벨만 브랜드 컬러 테두리로 강조된다.
- 축소하면 선택된 핀 라벨만 남고 나머지는 사라진다.

## 3. 결과 리스트

### 가게 카드 표시 항목

순위 번호 / 가게 이름 / 카테고리 / TrustScore (0~100) / 커뮤니티 평균 별점 (0~5) / 검색 중심으로부터의 거리 / 대표 이미지

로그인 상태에서 본인이 기록한 가게에 한해 아래 항목이 추가된다.

- **본인 코멘트** — 본인이 남긴 리뷰의 한 줄 코멘트 (`myStatus === 'reviewed'`일 때)
- **액션 버튼** — `myStatus`에 따라 카드 우측에 표시
  - `none` / `visited` → `리뷰 쓰기`
  - `reviewed` → `수정`

### 카드 클릭 영역

카드 내 영역별로 클릭 동작이 다르다.

| 클릭 영역 | 동작 |
|---|---|
| 카드 본체 (가게 이름·코멘트·액션 버튼 제외, 썸네일 포함) | 지도가 해당 가게로 클로즈업. 리스트와 viewport 검색은 그대로 유지 |
| 가게 이름 | 가게 상세 페이지로 이동. 이름 오른쪽에 `↗` 아이콘을 붙여 이동 가능함을 표시 |
| 본인 코멘트 줄 | 가게 상세 페이지로 이동 |
| 댓글 아이콘 + 리뷰 개수 | 가게 상세 페이지로 이동 |
| `리뷰 쓰기` / `수정` 버튼 | 리뷰 작성 페이지로 이동 |

### 지역 필터

시/도 → 시/군/구 두 단계 드롭다운. 선택 시 해당 지역 중심으로 지도가 이동하고 `page=1`로 리셋해 재검색한다. 검색바·카테고리 칩·"이 지역에서 검색"이 현재 이 역할을 우선 커버하므로, 지역 필터 UI 구현은 후속 작업이다. *(현재 미구현 — §6 참조)*

### 카테고리 필터

상단 칩(한식 / 일식 / 중식 / 양식 / 분식 / 치킨 / 패스트푸드 / 카페 / 술집 / 전체)을 누르면 해당 카테고리만 표시된다. 필터 변경 시 `page=1`로 리셋해 재검색한다.

### 정렬

리스트 헤더 우측의 드롭다운에서 선택한다. 정렬 변경 시 `page=1`로 리셋해 재검색(카테고리 필터와 동일 규칙).

- **랭킹순** (기본) — 내부 rank 오름차순. rank 계산식은 §6의 권장안(평균 별점 내림차순, 동점 시 TrustScore 내림차순) 참조.
- **신뢰도순** — 가게 TrustScore 내림차순. 신뢰할 수 있는 리뷰가 많이 쌓인 가게 우선.
- **최신순** — 가장 최근 리뷰 작성 시각 내림차순. 트렌드성 가게 발견용.

1차 MVP에서는 UI는 보이되 disabled 상태로 표시한다. 백엔드 정렬 파라미터 API 도착 시 활성화.

### 상황 필터 (2차 MVP)

"혼밥 / 데이트 / 회식 / 다이어트" 같은 상황 태그로 검색 결과를 좁히는 필터. 1차 MVP에서는 UI에 노출하지 않는다. 필터 신호의 출처는 Kakao 카테고리 추정이 아니라, 사용자가 리뷰 작성 시 직접 단 sceneTag의 가게별 누적 집계다. TrustBite의 "신뢰도 누적" 가치와 일치시키기 위함. 백엔드의 sceneTag aggregate API가 준비되면 필터 칩을 재노출한다.

### 페이지네이션 — "더 불러오기" 버튼

자동 무한 스크롤 없음. 버튼을 눌러야 추가로 불러온다.

- 기본 30개 표시.
- 결과가 더 있으면 리스트 맨 아래에 **"N개 더 불러오기"** 버튼 표시.
- 버튼을 누르면 다음 30개가 리스트 아래에 **추가**(덮어쓰기 아님)된다.
- 지도 핀도 새로 불러온 가게까지 포함해 함께 갱신된다.

## 4. 핀 ↔ 리스트 행 동기화

- **핀 클릭** → 해당 가게의 리스트 행으로 스크롤, 행 강조 표시
- **카드 클릭** → 지도에서 해당 핀 강조 + 그 가게로 클로즈업. 선택된 핀에는 이름 라벨(브랜드 컬러 테두리)이 표시된다. §5 Focus 모드와 달리 리스트와 viewport 검색은 그대로 유지됨

---

## 5. Focus 모드

§4의 카드 클릭 클로즈업과 달리, Focus 모드는 **결과 리스트와 viewport 검색까지 전부 한 가게로 좁힌다**. 진입 경로는 검색창에서 가게 확정뿐.

검색창에서 특정 가게를 확정하면(`search.md` 참조) 그 가게 하나에만 집중하는 상태가 된다.

- 지도: 핀 1개, 해당 가게로 클로즈업
- 리스트: 가게 카드 1개만 표시
- "이 지역에서 검색" / "더 불러오기" 버튼: 숨김
- **해제**: 검색창 지우기 / ESC / Clear(X) 버튼

## 6. 미정 · 논의 필요

- **랭킹 정렬 기준** — 커뮤니티 평균 별점 내림차순, 동점 시 TrustScore 내림차순이 권장안. 확정 필요.
- **대표 이미지 소스** — 현재 플레이스홀더 사용 중. 백엔드 이미지 정책 미정.
- **거리 기준점** — 현재 검색 중심 기준. 사용자 현재 위치 기준으로 바꿀지 논의 필요.
- **지역 필터 UI 구현 시점** — 검색바·"이 지역에서 검색"이 우선 커버. 백엔드 지역 API 준비 후 논의.
- **방문 체크 핀 UI 구현 시점** — 백엔드 `myStatus` API 연동 후 구현 예정.
- **시트(bottom sheet) 레이아웃 도입 여부** — PRD §7.2의 리스트 70-80% 우선 모델. 1차 MVP 이후 UX 검토 후 결정.
