# 1. 프로젝트 배경

### 1.1 기존 맛집 서비스의 문제

**평가를 믿을 수 없다**

- 절대평가(1~5점)는 리뷰가 쌓일수록 의미가 희석된다
- 영수증/사진 인증 등은 조작 가능하다
- 별점이 높아도 실제 만족도와 불일치하는 경우가 많다
- "이 별점은 왜 믿을 수 있는가?"에 답할 수 없다

**맛집 리스트를 함께 만들 수 없다**

- 친구·동료와 맛집을 공유하려면 메신저에 링크를 뿌리거나 별도 문서를 만들어야 한다
- 같이 가고 싶은 곳을 모아두고, 다녀온 곳을 기록하고, 그룹의 취향을 파악하는 기능이 없다
- 맛집 리스트는 본질적으로 혼자가 아니라 함께 만드는 콘텐츠인데, 기존 서비스는 모두 개인 단위로 설계되어 있다

### 1.2 TrustBite의 접근

TrustBite는 두 가지 문제를 동시에 푸는 프로젝트다. 평가의 신뢰도를 설계하고, 그 신뢰도 위에서 함께 맛집을 큐레이션하는 경험을 만든다.

| 기존 서비스             | TrustBite                                |
| ----------------------- | ---------------------------------------- |
| 하나의 숫자 (ex: 4.3점) | 다차원 평가 + 신뢰도 가중치              |
| 리뷰 수로 신뢰도 판단   | 리뷰어의 행동 패턴으로 신뢰도 계산       |
| 모든 리뷰 동일 비중     | 신뢰도 높은 리뷰어의 평가가 더 크게 반영 |
| 개인 단위 리스트        | 함께 만드는 리스트 + 그룹 취향 분석      |

**핵심 공식:** 최종 별점 = 사용자 입력 값 × 사용자 신뢰도(trustScore)

**핵심 경험:** 신뢰할 수 있는 평가를 바탕으로, 친구·동료와 함께 맛집 리스트를 만들고 취향을 발견한다

# 2. 신뢰도 시스템 (trustScore)

## 2.1 기본 원칙

- 모든 사용자는 0.0~1.0 사이의 trustScore를 가진다 (UI에서는 0~100%로 표시)
- 리뷰 5개 미만일 때는 신뢰도 대신 '평가 중'으로 표시
- **핵심: 등급은 trustScore의 결과물이지, 입력값이 아니다** (순환 참조 없음)

## 2.2 계산 공식

```
trustScore = (사진 충실도 × W₁) + (리뷰 충실도 × W₂) + (활동 꾸준함 × W₃) + (위치 인증률 × W₄) + (커뮤니티 평판 × W₅)
```

각 요소는 0.0~1.0 비율값이며, 가중치(W)의 합은 항상 1.0이다.

## 2.3 요소별 계산 방법 및 가중치

| 요소          | 계산 방법                         | 1차 MVP | 전체 |
| ------------- | --------------------------------- | ------- | ---- |
| 사진 충실도   | 사진 포함 리뷰 수 / 전체 리뷰 수  | 0.40    | 0.20 |
| 리뷰 충실도   | 100자 이상 리뷰 수 / 전체 리뷰 수 | 0.30    | 0.15 |
| 활동 꾸준함   | 최근 6개월 리뷰 수 / 전체 리뷰 수 | 0.30    | 0.15 |
| 위치 인증률   | 위치 인증 리뷰 수 / 전체 리뷰 수  | —       | 0.25 |
| 커뮤니티 평판 | 도움됐어요 비율 (cap 적용)        | —       | 0.25 |

1차 MVP에서는 위치 인증과 커뮤니티가 없으므로 나머지 3개 요소의 가중치를 재분배해 합계 1.0을 유지한다. 2차에서 요소가 추가되면 전체 버전 가중치로 전환한다.

## 2.4 계산 예시 (1차 MVP 기준)

**성실한 리뷰어 (유저 A):** 리뷰 10개 중 사진 8개(0.8), 100자+ 7개(0.7), 최근 6개월 9개(0.9)

```
0.8×0.4 + 0.7×0.3 + 0.9×0.3 = 0.80 → 신뢰도 80%
```

**대충 쓰는 유저 (유저 B):** 리뷰 10개 중 사진 2개(0.2), 100자+ 1개(0.1), 최근 6개월 3개(0.3)

```
0.2×0.4 + 0.1×0.3 + 0.3×0.3 = 0.20 → 신뢰도 20%
```

## 2.5 커뮤니티 평판 상세 (2차 MVP)

- **도움됐어요:** trustScore의 커뮤니티 평판 요소에 반영, 최대 +0.25 상한
- **신고 처리:** 전체 trustScore에서 직접 -0.05 차감 (요소 외 페널티)

## 2.6 시간 감쇠 — Decay (2차 MVP부터 적용)

```
decayFactor = e^(-0.005 × daysSinceReview)
weightedScore = 각 리뷰의 요소 점수 × decayFactor
trustScore = Σ(weightedScore) / Σ(decayFactor)
```

1차 MVP에서는 Decay 없이 단순 비율 계산. λ=0.005이면 약 140일(≈6개월) 후 가중치 절반으로 감소한다. 오래된 어뷰징 계정은 자연스럽게 trustScore가 낮아지고, 꾸준히 활동하는 유저의 영향력이 유지된다.

## 2.7 가게 점수 계산

```
가게 평점 = Σ(유저별점 × trustScore) / Σ(trustScore)
가게 신뢰도% = (Σ(reviewerTrustScore) / reviewerCount) × 100
```

평점이 높아도 신뢰도가 낮으면 '믿기 어려운 높은 점수', 평점이 보통이어도 신뢰도가 높으면 '검증된 평가'로 해석할 수 있다.

# 3. 등급 뱃지 시스템

등급은 trustScore와 리뷰 수로만 결정되며, trustScore 계산에 등급이 개입하지 않는다 (순환 참조 없음). 등급 변경은 리뷰 작성·삭제 시점에 자동 재판정한다.

| 단계 | 이름        | 리뷰 수 | 신뢰도 | 조건      | 예상 달성 기간   |
| ---- | ----------- | ------- | ------ | --------- | ---------------- |
| Lv.1 | 새싹        | —       | —      | 가입 즉시 | 즉시             |
| Lv.2 | 단골        | 3개+    | 30%+   | OR        | 약 1~2주         |
| Lv.3 | 맛집 수집가 | 10개+   | 40%+   | AND       | 약 1~2개월       |
| Lv.4 | 맛집 헌터   | 30개+   | 60%+   | AND       | 약 4~5개월       |
| Lv.5 | 미식가      | 70개+   | 75%+   | AND       | 약 8개월~1년     |
| Lv.6 | 미슐랭      | 150개+  | 90%+   | AND       | 약 1년 6개월~2년 |

- **단골(Lv.2)만 OR 조건인 이유:** 신규 유저가 빠르게 첫 등급 달성을 경험할 수 있도록 진입 장벽을 낮춤
- **맛집 수집가(Lv.3)부터 AND 조건인 이유:** 리뷰 수만 채운다고 등급이 오르지 않아 어뷰징 차단

## 3.1 뱃지 노출 위치

- 프로필 페이지 닉네임 옆
- 리뷰 카드의 작성자 정보 옆
- 헤더 우측 프로필 영역

## 3.2 등급 안내 화면

프로필의 뱃지 탭 또는 리뷰 제출 후 등급 진행 바를 탭하면 진입하는 별도 화면이다.

- 상단: 현재 등급 + 다음 등급까지 진행바 + '승급까지 남은 것' 체크리스트
- 하단: 전체 등급 타임라인 (달성/현재/미달성 시각적 구분)

# 4. 별점 시스템

## 4.1 맥락형 평점 (Context-based Rating)

단일 별점 대신 항목별 점수로 구성한다.

- 맛 (1~5점)
- 가성비 (1~5점)
- 분위기 (1~5점)
- 상황 태그: 혼밥 / 데이트 / 회식 (다중 선택)

상황별 추천(예: '데이트용 맛집만 보기')이 가능해지고, 평가에 맥락이 생겨 더 신중한 입력을 유도한다.

## 4.2 재방문 리뷰 정책

- 같은 가게에 재방문 시 새 리뷰 추가 가능 (히스토리 누적)
- visitCount는 리뷰 등록 이벤트에 의해 자동 집계 (유저 직접 입력 X)
- 동일 유저의 리뷰가 2개 이상이면 가로 캐러셀로 노출, 최신 리뷰가 첫 카드
- 각 카드에 방문 날짜 표시로 시간 흐름 파악 가능

```
카카오 Keyword API  →  위경도 포함 장소 데이터 수집
        +
카카오 지도 JS SDK  →  클러스터러로 마커 렌더링
        +
카카오 Category API →  지도 이동 시 주변 맛집 실시간 갱신
```

**리뷰/별점이 필요하다면** Google Places API를 서브로 붙이는 게 현실적입니다. 네이버·카카오 두 API 모두 자체 리뷰 데이터는 외부에 노출하지 않아요.

## 5.2 핀 구별

| 단계    | 적용 내용                                                                 |
| ------- | ------------------------------------------------------------------------- |
| 1차 MVP | 맛집 탐색 탭 지도: 단일 색상 핀 + 내 방문 체크 구분                       |
| 2차 MVP | trustScore 기반 핀 색상 차등 (골드/그린/그레이) + 나의 맛집 "지도로 보기" |
| 3차 MVP | 함께 만든 리스트 "지도로 보기" + 추가자 아바타 겹침                       |

## 맥락별 지도 핀 구성

### 1. 맛집 탐색 탭 (시트를 내려 지도 확장)

전체 맛집과 내 방문 기록이 겹쳐서 표시된다. 별도 전환 없이 항상 겹침.

| 핀 유형        | 스타일              | 설명                          |
| -------------- | ------------------- | ----------------------------- |
| 일반 맛집      | 기본 핀 (채워진 원) | 검색 결과 또는 해당 지역 맛집 |
| 내가 방문한 곳 | 기본 핀 + 체크 표시 | 내가 리뷰를 쓴 가게           |

- 1차 MVP: 단일 색상 핀 + 방문 체크만 구분
- 2차 MVP: trustScore 기반 색상 차등 추가 (골드: 신뢰도 80%+, 그린: 50~80%, 그레이: 50% 미만 또는 데이터 부족). 리뷰 10개 이상인 가게만 색상 차등 적용, 나머지는 기본 핀

### 2. 나의 맛집 → 내 랭킹 ("지도로 보기" 버튼)

내가 리뷰를 쓴 가게만 표시된다.

| 핀 유형      | 스타일    | 설명                        |
| ------------ | --------- | --------------------------- |
| 내 방문 가게 | 채워진 핀 | 내가 리뷰를 쓴 가게         |
| 가고 싶은 곳 | 반투명 핀 | 북마크한 가게 (아직 미방문) |

- 핀에 내 평점 순위 숫자 표시 가능
- 핀 탭 시 내 리뷰 미니 카드 노출
- 2차 MVP에서 추가

### 3. 함께 만든 리스트 ("지도로 보기" 버튼)

해당 그룹원들이 모은 가게만 표시된다.

| 핀 유형      | 스타일           | 설명                      |
| ------------ | ---------------- | ------------------------- |
| 다녀온 곳    | 채워진 핀        | 그룹원이 리뷰를 쓴 가게   |
| 가고 싶은 곳 | 테두리만 있는 핀 | 그룹원이 추가한 후보 가게 |

- 핀에 추가한 사람의 프로필 아바타를 겹쳐 표시
- "A는 강남 쪽, B는 홍대 쪽" 같은 지역별 패턴이 시각적으로 보임
- 핀 탭 시 추가자 정보 + 리뷰 미니 카드 노출
- 3차 MVP에서 함께 만든 리스트와 함께 추가

# 6. 신뢰도 체감 UX 설계

별도 설명 페이지 없이, 유저의 자연스러운 행동 안에서 신뢰도를 체감시킨다.

## 6.1 접점 1: 리뷰를 읽을 때

- 리뷰 카드에 '신뢰도 78%' + 등급 뱃지 + 방문 횟수 표시
- 신뢰도 숫자를 탭하면 바텀시트로 구성 요소 펼침 (사진 12회, 100자+ 8회 등)

## 6.2 접점 2: 리뷰를 쓸 때

- 사진 첨부 시 신뢰도 게이지 실시간 상승 (72% → 75%)
- 100자 넘기면 추가 상승
- 제출 버튼 위에 포인트 획득 및 신뢰도 변화 미리보기

## 6.3 접점 3: 가게 정보를 볼 때

- 맛집 상세 페이지에 '평점 4.3 / 신뢰도 88%' 병기 표시
- 신뢰도% 탭 시 리뷰어 신뢰도 분포 표시 ('5개 중 4개가 70%+ 리뷰어의 평가')

## 6.4 리뷰 제출 후 결과 화면

리뷰 제출 직후 신뢰도 변화를 명확하게 보여주는 결과 화면을 표시한다.

- **신뢰도 변화 애니메이션:** 72% → 77%로 게이지가 차오르는 시각적 보상감
- **항목별 기여 체크리스트:** 사진 +2.1%, 100자 이상 +1.4% 등 행동과 결과의 1:1 대응
- **등급 진행 바:** '맛집 헌터까지 리뷰 19개 남음' 같은 구체적 목표 제시

리뷰가 많아질수록 한 건의 영향이 줄어드는 비율 기반 특성은 등급 시스템이 보완한다. 숫자 변화는 작아도 등급이라는 큰 목표가 동기를 유지시킨다.

## 7.1 탭 구조 (2탭)

기존 3탭(지역 랭킹/맛집 지도/나의 맛집)에서 2탭으로 통합한다. 지도와 리스트를 분리하면 같은 데이터를 두 번 보여주게 되어 유저에게 불필요한 선택지를 준다.

| 탭   | 이름      | 접근 권한     | 설명                                   |
| ---- | --------- | ------------- | -------------------------------------- |
| 탭 1 | 맛집 탐색 | 비로그인 가능 | 지도+리스트 통합. 리스트 우선 디폴트   |
| 탭 2 | 나의 맛집 | 로그인 필요   | 내 랭킹 / 가고 싶은 / 함께 만든 리스트 |

## 7.2 탭 1 — 맛집 탐색

**디폴트 상태: 리스트 우선.** 화면의 70~80%를 랭킹 리스트가 차지하고, 상단에 지도가 살짝 보이는 상태. 시트를 아래로 내리면 지도가 넓어진다. TrustBite의 차별점은 '신뢰도 기반 순위'이므로, 순위가 먼저 눈에 들어와야 한다.

**상호작용 모델 — 지도가 곧 필터.** 지도와 리스트는 같은 데이터의 두 뷰다. 사용자가 지도를 이동·확대/축소하면 현재 보이는 영역(bounds)이 새로운 필터가 되고, 리스트는 그 영역 안의 맛집만으로 즉시 갱신된다. 반대로 리스트의 카드를 탭하면 지도 핀이 강조되고, 핀을 누르면 해당 카드로 스크롤된다. "검색"은 텍스트가 아니라 **지도를 움직이는 행위 자체**다 — 카카오 Category API로 지도 이동 시 주변 맛집을 실시간 갱신(§5.1 참조). 다만 지도를 살짝 흔드는 정도로는 갱신하지 않고, "이 지역 재검색" 버튼 또는 일정 이상 이동 시점에만 명시적으로 트리거한다(과도한 깜빡임 방지).

- 검색바 (Naver 검색 API 연동)
- 지역 필터 (시/구 드롭다운) + 정렬 필터 (랭킹순/신뢰도순/최신순)
- 카테고리 필터 칩 (전체/한식/일식/중식/양식…) + 상황 태그 필터 (혼밥/데이트/회식)
- 1~3위: 대형 이미지 카드 (순위 뱃지, 카테고리, 가게 이름, 평점+신뢰도%, 북마크)
- 4위~: 리스트 형태 (썸네일 + 가게명 + 카테고리 + 대표 리뷰 한 줄 + 신뢰도 + 평점 + 북마크)
- 추천 유저 카드 리스트 사이사이 혼합 노출 (같은 지역 고등급 유저, 팔로우 버튼)
- **첫 방문 인트로 카드:** 리스트 최상단에 1회만 노출. '여기 별점은 좀 다릅니다 — 검증된 리뷰어의 평가일수록 점수에 더 크게 반영돼요'

## 7.3 탭 2 — 나의 맛집

로그인 필수. 비로그인 시 로그인 유도 CTA 전체 화면 표시.

| 서브탭           | 설명                                                                                       | MVP 시점              |
| ---------------- | ------------------------------------------------------------------------------------------ | --------------------- |
| 내 랭킹          | 내가 리뷰를 쓴 가게 목록 (내 평점 순). 상단에 AI 취향 분석 및 레이더 차트                  | 1차(리스트) / 2차(AI) |
| 가고 싶은        | 맛집 상세에서 북마크로 추가한 가게 목록. '리뷰 쓰기' 버튼 → 방문 후 리뷰 작성 시 자동 제거 | 1차                   |
| 함께 만든 리스트 | 그룹별 리스트 카드. 각 그룹 내 '다녀온 곳 / 가고 싶은 곳'. 그룹 AI 취향 분석               | 3차                   |

## 7.4 함께 만든 리스트 상세 (3차 MVP)

- 그룹 생성 → 링크 초대 → 그룹별 리스트 자동 계산
- **다녀온 곳:** 그룹원이 리뷰를 쓴 가게 목록
- **가고 싶은 곳:** 그룹원이 추가한 후보 가게. 추가한 사람 + 뱃지 표시
- 가고 싶은 곳에서 방문 후 리뷰 작성 시 → '다녀온 곳'으로 자동 이동
- **그룹 AI 취향 분석:** '이 그룹은 한식 60%, 가성비 중시, 회식 맛집 공유 그룹'
- **멤버 간 취향 비교:** 'A는 분위기파, B는 가성비파 — 둘 다 만족할 가게는 이런 곳'
- **딥링크 유입:** 카카오톡 링크로 진입 시 해당 리스트 상세에 바로 랜딩 → '이 리스트에 참여하기' → 로그인 유도 → 나의 맛집 탭에 자동 추가

# 8. 화면별 구성 요소

## 8.1 공통 헤더

- 로고 (좌측)
- 닉네임 + 등급 뱃지 + 리뷰 수 + 신뢰도% + 프로필 사진 (우측)
- 비로그인 시: 로그인 버튼

## 8.2 맛집 상세 — 미리보기 (비로그인)

- 대표 사진 + 가게 기본 정보 (이름/카테고리/주소/영업시간)
- trustScore 가중 평균 점수 (맛/가성비/분위기 미니 바 차트)
- 리뷰 미리보기 2~3개 (닉네임+뱃지+방문횟수+별점+텍스트 2줄+사진)
- '리뷰 더 보기' → 로그인 유도 CTA 모달
- 헤더 우측 북마크 아이콘 → 나의 맛집 '가고 싶은' 탭에 바로 저장

## 8.3 맛집 상세 — 전체 (로그인)

- 대표 사진 가로 스크롤 갤러리
- trustScore 가중 평균 점수 + 항목별 점수 바 차트 + 상황 태그별 평균
- 전체 리뷰 리스트 (닉네임+뱃지+방문횟수+항목별점수+텍스트+사진+'도움됐어요')
- 재방문 리뷰 2개 이상 시 가로 캐러셀 (방문 날짜 표시)
- 리뷰 필터 (최신순/신뢰도순/상황 태그별)
- 하단 고정: 리뷰 쓰기 버튼

## 8.4 새 맛집 추가하기 (맛집 등록 + 별점 등록 통합)

데스크톱 기준 2컬럼 레이아웃.

- **좌측 컬럼 (입력):** 음식점 검색 (Naver API 자동완성) / 별점 평가 (맛/가성비/분위기) / 평가 텍스트 (100자 이상 권장) / 상황 태그 / 사진 업로드 / 위치 인증 버튼
- **우측 컬럼 (미리보기):** 현재 내 맛집 랭킹 리스트. 별점 입력 시 예상 순위 실시간 반영
- **제출 버튼 위:** 등록 시 획득 예정 보상 실시간 표시 (포인트, 신뢰도 변화)

## 8.5 로그인 + 온보딩

- 로고 + 서비스 한 줄 소개 + 구글 로그인 버튼
- 온보딩 모달 (최초 로그인 시 1회): 닉네임 입력 + 주요 활동 지역 선택 → 완료

## 8.6 내 프로필

- 상단: 프로필 사진 + 닉네임 + 등급 뱃지 + AI 취향 요약 + 리뷰 수/팔로워 수 + 포인트 잔액
- 획득한 뱃지 섹션 (컬러) + 미달성 뱃지 (그레이). 각 뱃지에 달성 조건 텍스트
- 미식 성향 분석: 레이더 차트 (맛/가성비/분위기) + 인생 맛집 TOP 3
- 하단 탭: 맛집 랭킹 / 가고 싶은
- 팔로워/팔로잉 카운트를 탭하면 본인의 팔로워·팔로잉 목록 화면(`/profile/followers`·`/profile/following`)으로 이동

## 8.6.1 팔로워·팔로잉 목록 (1차 MVP 추가)

팔로워 수 또는 팔로잉 수를 탭하면 진입. 본인용(`/profile/followers|following`)과 타 유저용(`/user/[id]/followers|following`) 라우트를 분리하되 동일 화면 컴포넌트를 재사용한다.

- **화면 구성:** 상단 탭(팔로워 / 팔로잉) + 유저 행 리스트(아바타·이름·핸들·등급·신뢰도 배지·팔로우 토글 버튼) + 빈 상태 메시지
- **탭 전환:** URL 세그먼트가 함께 변경됨(`router.replace`)
- **팔로우 토글:** 1차 MVP는 mock 데이터·로컬 상태. 본인 행에는 팔로우 버튼 미노출
- **실 API·페이지네이션·검색·필터:** 3차 MVP(W11)에서 구현

## 8.7 타 유저 프로필

- 프로필 + 팔로우 버튼 + 뱃지 + 미식 성향 분석
- 비팔로우 시: '팔로우하고 맛집 리스트를 확인해보세요' CTA
- 팔로우 + 포인트 부족 시: 포인트 적립 안내
- 팔로우 + 포인트 충분 시: '맛집 리스트 열람하기 (-10pt)' 버튼
- 팔로워/팔로잉 카운트를 탭하면 해당 유저의 목록 화면(`/user/[id]/followers`·`/user/[id]/following`)으로 이동

# 16. 화면 플로우

### 1-1) 첫방문 → 리뷰 작성

비로그인 탐색 → 리뷰 더 보기 CTA → 로그인으로 이어지는 깔때기예요. 핵심은 맛집 상세 미리보기에서 "더 보고 싶다"는 욕구를 만드는 건데, 신뢰도%가 붙은 리뷰 카드가 기존 서비스와 다르게 보이기 때문에 호기심이 생기는 구조입니다.

### 1-2) 리뷰 작성 → 신뢰도 상승

비스의 심장이에요. 리뷰를 쓰면 → 제출 결과에서 신뢰도 상승을 체감하고 → 등급 안내 화면에서 "다음 등급까지 얼마 안 남았네"를 확인하고 → 다시 탐색으로 돌아가는 반복 구조입니다. 이 루프가 돌아야 trustScore 데이터가 쌓이고, 서비스 전체의 가치가 올라갑니다.

### 1-3) 소셜

두 갈래 진입인데, 앱 안에서 유저를 발견하는 경로와 카카오톡 링크로 외부에서 유입되는 경로가 있어요. 두 경로 모두 결국 "리뷰를 써야 포인트가 생기고, 포인트가 있어야 다른 사람 리스트를 볼 수 있다"는 구조라서 Flow 2의 리뷰 루프로 다시 수렴합니다.
